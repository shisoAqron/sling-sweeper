# 🪨 スリングスイーパー (Sling Sweeper)

マインスイーパー × おはじき。マスを直接クリックする代わりに、固定の発射台から石を弾き、**石の中心が止まったマス**を開く。
爆弾に当たってもゲームオーバーにはならず、ミス数が増えるだけ。前回の着地点を見て角度と引っ張り量を補正しよう。

## 🎮 遊ぶ

**https://shisoaqron.github.io/sling-sweeper/**

ブラウザだけで動く（PC・スマホ対応）。インストールやアカウント登録は不要。

仕様の詳細は [AGENTS.md](./AGENTS.md) を参照。

## 開発

```sh
npm install
npm run dev        # 開発サーバ。http://localhost:5173/?dev で開発用UI（発射倍率スライダー）を表示
npm test           # 単体テスト（Vitest）
npm run build      # 型チェック + 本番ビルド（dist/）
```

`?dev` の開発用UIで倍率を触ったゲームは、記録を保存しない。

## 構成

| パス | 内容 |
| --- | --- |
| `src/core/` | DOM/Canvas 非依存の純粋ロジック（射出計算・盤面・ゲーム状態・乱数・日替わり・共有文） |
| `src/storage.ts` | `localStorage` の保存・記録（スキーマバージョン付き） |
| `src/view.ts` | 画面座標 ⇔ 論理座標の変換 |
| `src/render.ts` | Canvas 描画 |
| `src/main.ts` | 入力・画面遷移・UI |

- 距離・角度はすべて盤面に紐づく**論理座標**（盤面の一辺 = 100）で計算する。画面サイズ・DPR・フレームレートは判定に影響しない。
- 停止セルは `fireShot()` が入力だけから先に確定し、画面の石は見た目だけ減速アニメーションする。
- 盤面と発射倍率はシード付き乱数（`Math.random()` 不使用）から生成する。日替わりの種は `アルゴリズムver|日付(JST)|難易度`。生成ロジックを変えるときは `ALGORITHM_VERSION` を上げる。
- Vite の `base` は `./`（相対）なので、`/sling-sweeper/` のようなサブパス配信でも動く。`main` への push で `.github/workflows/deploy.yml` が GitHub Pages へデプロイする（リポジトリ設定で Pages のソースを "GitHub Actions" にする）。

## 暫定仕様・判断事項（AGENTS.md「未決定事項」への対応）

実装時に既定値で仮置きした項目。遊んで調整する。

1. **既に見えている爆弾への再着地**: 毎回ミス +1（暫定仕様のまま）。`src/core/game.ts` の `mine-again`。
2. **発射倍率の範囲**: 3.2〜4.4、引っ張り上限 40、最小引っ張り 2（`src/core/constants.ts`）。最小倍率でも全難易度の最遠マス中心に届き、最大倍率でも最近マスを狙えることをテストで確認している。減速アニメは easeOutCubic、450〜1100ms。
3. **難易度**: Easy 6×6(地雷5) / Standard 8×8(10) / Normal 10×10(15) / Hard 16×16(40)。地雷数は仮。
4. **旗**: 未実装（MVP 対象外）。
5. **デイリーの記録**: 日付・難易度ごとに「初回クリア」と「ベスト」を分けて保存。リトライ回数の制限はなし。日替わりの「やり直し」は同じ盤面でのリトライ。
6. **操作**: ドラッグは盤面のどこから始めてもよく、開始点からの相対量で引く（発射台に触れる必要はない）。後方（盤面と反対側）への射出と、引っ張りが短すぎる操作はキャンセルで投数に加算しない。
7. **日替わりの難易度**: 難易度ごとに別の盤面・記録（種に難易度を含めるため）。
